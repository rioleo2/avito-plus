# Avito Plus

Самостоятельный веб-сервис для поиска объявлений по фильтрам, сравнения цен и пояснения характеристик товара. Репозиторий: https://github.com/rioleo2/avito-plus.

## Состояние на 15.10.2026

Передан локальный прототип: FastAPI, Pydantic, Jinja/JavaScript, Playwright Firefox и необязательный по целевой архитектуре AI-анализ. Исходники переданы локально и остаются в исходной папке; их запуск/качество не проверялись исполнением. Эта ветка публикует только документацию/каркас/канбан: исходный Python/JS/HTML код ещё не импортирован. В пустом GitHub создан отдельный минимальный bootstrap main для review PR; локальная исходная папка не превращалась в checkout.

Подготовлены документация, целевая структура и файловый канбан. Код не перенесён и не изменён, личные браузерные профили сохранены на месте и исключены из будущего Git/Docker context.

## Первый рабочий этап

Безопасный allowlist импорт → зависимости/конфигурация → перенос в пакет без смены API → честная выдача/фильтры/защита → локальная приёмка → закрытый пилот на ВМ → публичный запуск. Структурный перенос не считается готовностью сервиса.

Ключевые ограничения прототипа: Windows cookies, неподтверждённые/генерируемые fallback-объявления, часть фильтров не работает, HTML-интерполяция внешнего текста, localhost LM Studio. Подробности и ссылки на задачи — в BASELINE.

## Запуск

Пока воспроизводимая установка не подготовлена: requirements.in — список прямых runtime-зависимостей по исходникам, не lock и не проверенное окружение. Не запускать test_*.py как обычную offline suite: среди них live запросы/браузеры/локальный AI. Новый пакет src/avito_plus пока содержит только README; команда будущего production entrypoint станет доступна после AP-003.

Лицензия не назначена: согласовать с автором право публикации/использования и подходящую LICENSE перед первым импортом в public repo. Не публиковать browser profiles, cookies, историю пользователя или debug captures.

**На GitHub** нажимайте ссылки в таблице. Файловые папки — простой канбан, а не автоматически настроенный GitHub Projects. **При работе локально** открывайте те же Markdown-файлы в редакторе или передавайте их Claude.

### Как устроены задачи

```text
tasks/to-do/         запланировано
tasks/in-progress/   реально выполняется
tasks/done/          получен результат и записано подтверждение
```

У каждой задачи постоянный номер AP-NNN, цель, зависимости, границы изменений и критерии приёмки. Например, AP-014 отвечает за соответствие товара, цены и ссылки. Папка определяет статус; BOARD.md помогает ориентироваться и обновляется вместе с переносом файла. Не копируйте одну задачу в несколько папок.

Если не хватает входных данных — укажите Blocked и причину в файле, не ставьте Done. Подготовленный план/код/локальная проверка/публикация/работа на сервере — разные результаты. В done сейчас только AP-000: готовность этой документации, не приложения.

### С чего начать

1. Прочитайте LAUNCH_BLOCKERS и AP-001: сначала чистый импорт исходников и права публикации.
2. Выберите **одну** задачу, у которой выполнены зависимости. Передайте Claude её номер, файл и разрешённый scope.
3. При работе в Git используйте отдельную ветку. Не публикуйте всю исходную папку: там есть личные browser profiles и debug captures.
4. Перед изменениями проверьте актуальные файлы и чужую работу. Начатую задачу перенесите в in-progress; если сейчас выполняется только обсуждение — оставьте to-do.
5. Посмотрите diff и отчёт Claude: что изменилось, что проверялось и что осталось. Тесты поручайте явно; live Avito/AI/browser проверки требуют отдельного решения.
6. После принятия результата перенесите задачу в done, запишите commit/PR/проверки и обновите BOARD. Публикация кода не означает, что сервис уже развёрнут.

Пока исходники не импортированы, Claude не сможет реализовать задачу по одному описанию структуры. Нужно сначала передать авторские исходники через AP-001; личные профили/cookies не требуются и не должны попадать в Git.

### Что считаем полезной первой версией

Пользователь задаёт запрос, видит несколько страниц **реальных** объявлений, достоверные цены/ссылки и доступные фотографии. При недоступном источнике получает понятную ошибку. Затем сервис ранжирует сравнимые предложения и объясняет выбор; это лучшие варианты в собранной выборке, а не обещание найти лучшее объявление на всём рынке.

Сначала исправляем достоверность (AP-004/AP-014), затем количество/страницы (AP-005), фото (AP-013) и рекомендации (AP-015). AI не обязателен для первого полезного поиска.
