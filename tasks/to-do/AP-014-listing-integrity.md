# AP-014 — соответствие цены, товара и ссылки

Priority: P0. Owner: UNASSIGNED. Blocked: source contract AP-006.

## Запрос пользователя
Встречаются карточки с одной ценой/товаром, а после перехода открывается другое. Исправить достоверность результата до рекомендаций.

## Факты и гипотеза
Пользователь сообщает несовпадения. Конкретные URL/время не предоставлены, live причина не воспроизведена. Статически найден silent curated/generated fallback, generic search/category links и переписывание города без изменения исходной ссылки. Это вероятный источник части ошибок, а не доказанная причина каждого случая.

## Scope
Убрать неподтверждённые fallback карточки из real mode (AP-004). Извлекать ID/title/price/location/photo/canonical URL из одной записи источника. Listing URL должен вести на конкретный товар, не поиск/категорию. Не собирать URL строковой конкатенацией без URL parsing/host checks. Отделять variant/цена-от/неизвестная цена; не извлекать цену из постороннего текста карточки.

Сохранять fetched_at, source и observed_price; stale cached result маркировать. Если цена изменилась/объявление снято — показать это по доступному подтверждению. Не обещать неизменность цены после сбора. Detail check только bounded/по выбранному источнику, без обязательного двойного обхода всех карточек и без обхода блокировки.

## Зависимости
AP-004, AP-006, AP-008. Не менять root source в рамках одной документационной задачи.

## Приёмка
- ID/card URL/title/price согласованы; search/category URL не выдаётся за конкретный товар.
- Есть offline cases: relative/absolute/malformed URL, category link, изменённая/отсутствующая цена, дубли, снятое/устаревшее объявление.
- Нет generated live items и подменённой локации; вывод source/time виден пользователю.
- Для separately authorized live pilot сопоставить небольшой набор карточек с исходниками, записать mismatch и ограничения, не публиковать raw pages/личные данные.

## Результат
NOT_STARTED. Пользовательский дефект принят в backlog; причина по конкретному объявлению UNKNOWN.
