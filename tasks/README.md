# Файловый канбан

Статус определяет папка: to-do → in-progress → done. [Доска](BOARD.md) — обзор, не независимый реестр.

Каждая задача имеет постоянный ID и один файл. При старте указать исполнителя/ветку, перенести файл в in-progress и обновить доску. После результата/review перенести в done и записать доказательства/ограничения. Если блокер — оставить незавершённый статус и указать Blocked/причину внутри; не создавать копию задачи в другой папке. Новая существенная цель — новый ID, небольшое уточнение сохраняет ID.

Не смешивать code ready, опубликовано и deployed. Не заполнять Done заранее. GitHub Projects/Issues можно подключить позже, сначала выбрать один источник статуса; автоматической синхронизации папок с Jira нет.
